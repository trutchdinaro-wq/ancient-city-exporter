# Ancient City Exporter

Офлайн-тулка для поиска городов вардена (Ancient City) по сиду Minecraft Java Edition. Выдаёт готовую строку **`X Z; X Z; X Z`** для Warden Shrieker Loot.

## Для Windows

Скачайте **AncientCityExporter.exe** из [Releases](../../releases/latest), запустите, введите числовой сид и нажмите **Найти города**. Затем **Скопировать для скрипта** → вставьте в настройку **Свои города X Z; X Z**. Python, Java и Minecraft для готового EXE не нужны.

- Сид обрабатывается как точное знаковое 64-битное число: последние цифры не теряются.
- По умолчанию область `−15900 ≤ X,Z ≤ 15900`, квадрат вокруг нуля. Можно уменьшить границу. Верхний предел соответствует текущему скрипту.
- Выдаются все найденные движком города внутри выбранной области, без лимита количества. Не весь бесконечный мир.
- Отмена прерывает расчёт; незавершённые координаты не выдаются за полный результат.
- Есть копирование и сохранение в `.txt`. При нуле городов кнопка копирования отключена: пустое поле скрипта включает его встроенный маршрут.
- Программа ничего не отправляет в сеть, не читает файлы Minecraft и не меняет скрипты.

## Точность и версии

Движок — [Cubiomes](https://github.com/Cubitect/cubiomes), зафиксированная ревизия `e61f90580cbdd883214a8054670dacae655e59c0`. Проверяются позиция структуры, биом и рельеф. Это предсказание стандартной генерации **Java, обычные биомы**, а не чтение существующего мира. Серверные генераторы, датапаки, старые чанки, large biomes и изменённый мир могут давать другие результаты.

Названия 1.19 / 1.20 / 1.21 соответствуют `MC_1_19` / `MC_1_20` / `MC_1_21` этой ревизии библиотеки. Это не отдельная проверенная реализация каждой последующей патч-версии: в частности, точность для 1.21.11 не гарантируется. Координаты — опорные X/Z структуры, а не координаты каждого крикуна или границы города. Алгоритм структуры не находит отдельные участки Deep Dark без городов.

## Из исходников

Python 3.11+ с Tkinter и GCC/Clang (либо Zig C compiler). Зависимости Cubiomes уже в `vendor/`, сеть для расчёта и сборки C-движка не нужна.

```sh
python build.py
python app.py
```

Другой компилятор задаётся переменной окружения `CC`, например `CC="zig cc"`. В Windows с путями, содержащими пробелы, удобнее добавить компилятор в PATH.

CLI без интерфейса:

```sh
./city-engine 12345 15900 1.21 > cities.txt
# Windows:
city-engine.exe 12345 15900 1.21 > cities.txt
```

В stdout только координаты, прогресс и количество — в stderr. Пустой результат считается успешным. Неверные аргументы возвращают код 2.

Тесты после сборки: `python -m unittest discover -s tests -v`.

Сборка Windows EXE:

```sh
python -m pip install -r requirements-build.txt
python -m PyInstaller --noconfirm --onefile --windowed --name AncientCityExporter --add-binary "city-engine.exe;." app.py
```
